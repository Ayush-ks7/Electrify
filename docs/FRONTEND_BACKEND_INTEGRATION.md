# Frontend / backend integration

Updated for the utility workspace overhaul, 4 October 2026. This replaces the previous route-redirection/demo-profile interface.

## Architecture

`Page → React Query hook → operations service → HTTP adapter → FastAPI operations service → database / existing investigation service`.

- `src/workspace/`: pages, shared UI, hooks, presentation service, HTTP adapter and export utility.
- `src/services/api.ts`: retained timeout/cancellation/auth/error-aware client and original scoring contracts.
- `backend/app/core/topology.py`: single canonical transformer/consumer mapping. All frontend views obtain it from the same operations response.
- `backend/app/services/operations_service.py`: window alignment, simulated transformer input, residual calculation, finding snapshots, case persistence.
- `backend/app/services/simulation_service.py`: existing scheduler and model integration; targets now use canonical IDs.
- `ai_ml/Electrify_AI_ML_Final/`: unchanged locked model, 24-feature contract, full-history inference.

The adapter deliberately has no silent offline mock fallback. A backend outage displays an error and Retry. Uninitialized locality meters have an explicit illustrative baseline preview generated by the backend, not hardcoded page records.

## APIs

All new operations routes share existing API-key dependencies and CORS settings.

| Method | Route | Purpose |
| --- | --- | --- |
| GET | /api/v1/operations?days=7 or 30 | Canonical locality, aligned daily histories, transformer balance, persisted findings and cases |
| POST | /api/v1/operations/cases | Create one case for an anomaly; body: anomaly_id; repeated creation returns existing case |
| POST | /api/v1/operations/cases/{id}/status | Open, Under Review, Confirmed, False Positive, Resolved |
| POST | /api/v1/operations/cases/{id}/notes | Nonblank note, at most 4,000 characters; neutral activity log |
| GET | /api/v1/simulation | Existing scheduler state |
| POST | /api/v1/simulation/start | Existing targets/speed contract, now C01–C20 canonical synthetic sources |
| POST | /api/v1/simulation/stop or reset | Existing stream controls; UI explicitly passes locality-owned stream IDs |
| POST | /api/v1/score-history | Existing stored-history scoring, unchanged feature generation |
| GET | /health and /api/v1/model-info | Connection state and secondary model information |

Existing generic consumer/history/risk/scoring and legacy investigation APIs remain available. Original stored consumers are never overwritten or deleted by locality controls.

## Data meaning

- Daily time windows are inclusive calendar dates in UTC and end at the latest completed simulated day or yesterday. Accelerated streams can extend beyond real time.
- Residual = transformer input − sum of connected consumer energy. Residual % = residual / input × 100. A missing/invalid consumer reading makes that daily residual unavailable; an incomplete window has no aggregate residual. Zero input yields no percentage.
- Transformer input is generated supply × 1.045. Supply follows load before reported meter faults/under-reporting; dates without generated supply use illustrative baseline input. This is not validated network-loss measurement. The illustrative review band is |residual %| > 10.
- Preview consumer histories are deterministic illustrative daily baselines. Starting a target creates the existing isolated synthetic history/telemetry stream and overlays its persisted daily values.
- Fixed historical baseline and connected-peer mean are descriptive UI comparisons, never additional model features. A peer gap makes that day's peer average unavailable.
- Risk probability, screening threshold, signals and warnings come only from saved locked-model results. No anomaly-score percentage or trained cause probabilities are manufactured.
- Cause explanations and priority labels come from existing operational rules. “Confirmed” is a human case decision, not an automatic theft classification.
- Quality score = non-negative present daily values / expected values. Duplicate counts inspect stored dates; the database enforces consumer/date uniqueness. Ingestion duplicate/rejection rates are unavailable.
- Unfiled findings track current evidence, one per run/scenario episode. Creating a case freezes its snapshot. Reset removes unfiled simulation findings and generated streams; human-created cases and their evidence survive with simulated provenance.
- New and switched simulation runs use distinct run IDs; switching clears that target's generated history and scores back to its original baseline. Initial and daily scores use the existing model, and UI risk is the saved review probability. Reset cancels stale reads and clears cached workspace projections before baseline data is fetched.
- Old owned demo source aliases migrate to canonical source IDs on restart without dropping their persisted histories.

## Routes

Primary: /overview, /locality, /consumers, /anomalies, /cases, /data-quality, /simulation.
Details: /consumers/:id, /anomalies/:id; case selection uses /cases?case=ID.
Root and /dashboard redirect to /overview; /alerts → /anomalies; /analytics and /system → /overview.
Model information is a secondary sidebar drawer. Unknown routes show a useful not-found state.

## Interaction and performance

Locality dependencies are route/view lazy-loaded. R3F renders on demand with shared geometry/materials; camera framing adapts to viewport size. Cytoscape uses fixed initial positions and no ongoing force simulation; dragging survives polling. Both views use the same drawer and accessible node list.

GSAP animates page/drawer/locality entrance only. Lenis preserves native keyboard and touch scrolling, excludes drawers and locality gestures, and is disabled for reduced motion. Hidden scrollbars preserve scrollability. Charts have titles, axes/units, legends, tooltips, null gaps and accessible data tables.

Reference implementation APIs: [R3F demand rendering](https://r3f.docs.pmnd.rs/advanced/scaling-performance), [Cytoscape preset layout](https://js.cytoscape.org/), [GSAP reduced-motion contexts](https://gsap.com/docs/v3/GSAP/gsap.matchMedia()/).
